## 1. 场景一句话

**深夜的卧室：会魔法的女仆「鲸鲸」侍奉你入睡——关灯、更衣、引你到床边、讲睡前故事；清晨她拉开窗帘，把你唤醒。**

- **世界**：现代奇幻，欧式小卧室，窗外是夜；第二幕同一房间，天光。
- **氛围**：暖黄台灯 vs 冷蓝月光；亲密、安静、被照顾。
- **NPC**：**鲸鲸**，1 个可对话女仆，会魔法（关灯 / 掀窗帘在设定上是法术，视觉用粒子收尾）。注意：**设定上的魔法不解决指令问题**，关灯 / 窗帘 / 更衣仍需显式的状态指令（§2 `set`）。
- **两幕**：夜（侍寝）→ 晨（唤醒）。同一房间、同一套锚点与指令，靠 `set curtain` / `set light` 切换光照与天空盒；**先做侍寝，唤醒在 v1.5**。
  - 侍寝顺序（v1）：问候 → 更衣 → **膝枕小睡** → 起身 → 引到床边 → 关灯 → 睡前故事 → 晚安。
- **玩家视角**：第一人称，固定眼高，WASD 走动（v1 必做，约 3h；时间紧退化为固定机位，指令不受影响）。
- **膝枕小睡（POV）**：鲸鲸坐在床边，你枕在她腿上；镜头从膝上向上看她，她低头、轻抚发丝（手部可省略，用发丝摆动与阴影代替）；灯光调暗，3 秒轻哼过渡 → 她说「就一会儿」→ 你随时说「起来」退出。

### 角色：鲸鲸

- 称呼玩家「你」；自称「鲸鲸」。
- 语气：温柔、慢半拍、偶尔撒娇；做事利落但不冷。
- 开场白（草案，替换 Kimi 版）：「回来啦。外面风大，先脱外套吧。要鲸鲸把灯调暗一点吗？」
- 边界：不出戏、不解释 JSON、不复述系统提示、不替玩家做决定。
- ❓ 开场白可改；改了就同步到服务端 `prompt.md`。

### 空间与锚点

房间约 5m × 6m，床靠后墙，7 个锚点：

| id | 中文 | 语义（写进提示词的就是这句） | 位置 |
|---|---|---|---|
| `bed` | 床边 | 大床，被子叠着，床头一盏灯（女仆默认位） | 后墙正中 |
| `window` | 窗边 | 落地窗，夜里有月亮，清晨有阳光 | 北墙 |
| `screen` | 屏风 | 三折屏风，换衣服的地方 | 东侧 |
| `desk` | 梳妆台 | 镜子、梳子，台灯是主光源 | 西墙 |
| `lamp` | 台灯 | 床头灯，可开可关 | 床头 |
| `door` | 门口 | 房门，门外是走廊 | 南墙 |
| `player` | 你 | 玩家位置（伪锚点：只作 `look_at` 目标，不可寻路、不可 spawn） | 动态 |

锚点图（`move` 的可行路径，BFS 最短路）：

```
door ── bed ── window
          │
        screen ── desk
```

边：`door–bed`、`bed–window`、`bed–screen`、`screen–desk`。
❓ 建场景时按实际摆位微调边，锚点 id 不变。

**为什么用锚点图而不是 NavMesh**：50h 里 Unity 零基础，NavMesh 要烘焙 + 调参 + 排错；锚点图是"预设点 + 预设边 + 直线插值"，确定、可调试，而且和"LLM 只在语义锚点里选"的设定天然一致。

## 2. 四条指令的参数格式

统一结构：`{"op": "<指令>", ...参数}`，`op` 四选一。第 4 条 `set` 是卧室场景新增的——关灯 / 窗帘 / 更衣都是**状态切换**，不是空间动作，`spawn/move/look_at` 表达不了；这是范围变更，成本约 +3–4h。

| op | 参数 | 语义 | 合法条件 | 非法时 |
|---|---|---|---|---|
| `spawn` | `anchor`（必填）、`name`（选填，≤8 字） | 在锚点召唤一只夜灯精灵 | 锚点存在且不是 `player`；场上 ≤ 5 只 | 整批丢弃 |
| `move` | `entity`（必填：`npc` 或 `wisp_N`）、`anchor`（必填） | NPC 沿锚点图走过去；精灵直线飘过去 | 实体存在；锚点存在；`player` 不可作目的地 | 整批丢弃 |
| `look_at` | `entity`（必填，目前只有 `npc`）、`target`（必填：锚点名或 `player`） | NPC 转身面向目标（0.5s 平滑转身） | 实体存在；target 存在 | 整批丢弃 |
| `set` | `target`（必填：`light` / `curtain` / `outfit` / `npc` / `player`）、`state`（必填） | `light`: on/off；`curtain`: open/closed；`outfit`: nightgown/daydress；`npc`: sit/stand；`player`: lap/stand | target、state 在枚举内；`player=lap` 需 npc 在 `bed` 且 `npc=sit` | 整批丢弃 |

约定：

- **更衣** = `move(screen)` + `set(outfit, daydress)`；屏风遮挡 + 1s 淡入切模型。
- **关灯** = `set(light, off)`；台灯光强与房间环境光同步降，窗外月光保留。
- **唤醒** = `set(curtain, open)` + `set(light, off)` + `say`；阳光进，天空盒切日间。
- **膝枕** = `set(npc, sit)` + `set(player, lap)`（前提：npc 在 `bed`）；镜头从膝上向上看，输入锁定；退出 = `set(player, stand)` 或任何 `move`。
- `entity` 在提示词里要求显式写；客户端缺省按 `npc` 处理。
- 精灵 id 由客户端生成：`wisp_1`、`wisp_2`……
- **不做**（v2 再说）：自由坐标、自由寻路、生成可对话 NPC、自由换装/换材质、多场景。

## 3. LLM 返回格式

### 响应（LLM → 客户端）

```json
{
  "say": "好，我关灯了。晚安。",
  "commands": [
    { "op": "move",    "entity": "npc", "anchor": "bed" },
    { "op": "look_at", "entity": "npc", "target": "player" },
    { "op": "set",     "target": "light", "state": "off" }
  ]
}
```

| 字段 | 类型 | 规则 |
|---|---|---|
| `say` | string | 角色口吻，≤4 句（讲故事类 ≤6 句 / ≤200 字），可空串；先播这句，再执行指令 |
| `commands` | array | 0–5 条，按序执行；空数组 = 只说话 |

### 请求（Unity → 编排服务）

```json
{
  "player_text": "关灯，然后到床边看着我",
  "world": {
    "anchors": [
      { "id": "bed",    "desc": "大床，被子叠着，床头一盏灯" },
      { "id": "window", "desc": "落地窗，夜里有月亮" },
      { "id": "screen", "desc": "三折屏风，换衣服的地方" },
      { "id": "desk",   "desc": "梳妆台，镜子与梳子" },
      { "id": "door",   "desc": "房门，门外是走廊" }
    ],
    "entities": [
      { "id": "npc", "kind": "npc", "at": "bed" }
    ]
  }
}
```

`world` 就是"世界快照"：LLM 只能从快照里选锚点和实体，选不存在的就判非法。这是不做自由寻路还能"看起来智能"的关键。

### 校验与失败策略（两层）

1. **服务端**：严格 JSON 解析 + 结构校验（字段、枚举、数量）。失败 → 带错误信息重问 **1 次**；仍失败 → 兜底 `{"say": "……我好像没听清，再说一遍？", "commands": []}`。
2. **客户端**：执行前**全量校验**（op 合法 / 实体存在 / 锚点存在 / ≤5 条）。任一非法 → **整批不执行**（不做半截），NPC 说"这个我做不到"，Console 打日志。
3. 执行顺序：先播 `say`（打字机），再逐条执行，条间 0.3s 缓冲；`say` 为空则直接执行。
4. **提示词规则**：允许 `commands: []` 的纯对话（反问 / 澄清 / 拒绝）；允许从非指令推断（"我困了" → 关灯 + 引床）；禁止编造锚点 / 实体 / 指令；拿不准时先问一句再做。

### 兜底（对着录屏用）

服务端带 `--offline` 开关：读 `demo_lines.json`，按 `player_text` 精确匹配返回预置响应；匹配不到走固定话术。录屏时打开，不怕断网 / 限流 / 模型抖动。

## 4. 技术架构

```
Unity 客户端                        FastAPI 编排服务                  LLM（OpenAI 兼容）
┌───────────────────────┐   HTTP    ┌──────────────────────┐   HTTPS   ┌──────────────────┐
│ DialogueUI（输入/气泡） │ ────────> │ POST /direct         │ ────────> │ chat/completions │
│ DirectorClient        │ <──────── │ 提示词组装+校验+重试   │ <──────── │                  │
│ WorldState（锚点/实体） │           │ 日志                 │           └──────────────────┘
│ CommandExecutor       │           │ GET /health          │
│ AnchorGraph / NpcAgent│           │ --offline 回放        │
│ WispSpawner           │           └──────────────────────┘
└───────────────────────┘
```

- **Unity 6 LTS + URP 3D 模板**；Bloom 后期；TextMesh Pro；JSON 用 Newtonsoft（`com.unity.nuget.newtonsoft-json`）。
- **不让 Unity 直连大模型**：API Key 不能进客户端；校验 / 重试 / 日志在服务端才像工程；换模型只改一处。
- 服务端为本仓库自带的小服务（**不依赖已有桌宠后端**），约 150–200 行：`POST /direct`、`GET /health`、离线回放。
- 多轮：服务端保留最近 10 轮上下文（内存，重启清空）；长期记忆 v2。
- 每轮写 `server/logs/turns.jsonl`（输入 / 输出 / 是否合法 / 耗时），本地排查与录屏复盘用；`logs/` 不入库。
- 延迟预算：首字 < 2s；Unity 请求超时 8s，超时 → 兜底话术，不卡死。

### Unity 侧模块

| 模块 | 职责 | 估算 |
|---|---|---|
| `WorldState` | 锚点表（7）、实体表（npc + wisps）、当前位置 | 2h |
| `AnchorGraph` | 邻接表 + BFS 最短路 | 2h |
| `NpcAgent` | 沿路径插值走（1.2 m/s）+ 到点转身；`look_at` 平滑转向；换装淡入 | 4h |
| `WispSpawner / WispMotion` | 发光球 + 点光 + 上下浮动；飘向锚点 | 3h |
| `StateSwitcher` | 台灯 / 窗帘 / 服装三态；光照与天空盒联动 | 3h |
| `PoseCamera` | 坐姿 / 膝枕机位 / 起身过渡 / 输入锁 | 2h |
| `CommandExecutor` | 逐条执行 + 校验 + 日志（4 类 op） | 3h |
| `DialogueUI` | 输入框、气泡、打字机、"思考中"提示 | 3h |
| `DirectorClient` | UnityWebRequest + JSON + 超时 | 2h |
| `PlayerController`（P1） | 第一人称走动 | 3h |

## 7. AI 必要性证据（录屏必拍）

> 防止 demo 被看成"文字版对话树"。下面 5 个镜头必须出现在录屏里——它们都是 LLM 才做得到、查表做不了的。

| # | 镜头 | 为什么脚本做不了 |
