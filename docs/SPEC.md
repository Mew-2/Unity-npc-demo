## 1. 场景一句话

**夜里的灯塔小屋：守灯的女孩「阿澄」住在海边灯塔下的小屋里。玩家推门进来，用自然语言请她做事——她会走到窗边、在炉边停下、看向你，或替你召唤一只发光的灯灵。**

- **世界**：现代奇幻，海边，夜。只有这一间屋；窗外是海和灯塔扫过的光，不外出。
- **氛围**：暖黄灯光 vs 冷蓝夜色；安静、亲密、有微光——"有人等你回来"的感觉。
- **NPC**：**1 个可对话 NPC**（阿澄）+ **可召唤的灯灵**（发光小精灵，不对话，只会漂浮/飘向锚点）。
  - 一个 NPC 保住对话深度；灯灵负责让"世界被改变"在视觉上成立，也把 `spawn` 用上。
  - ❓ 名字/气质可换（更机娘、更冷淡、更话痨都行），v1 前定。
- **玩家视角**：第一人称，固定眼高，WASD 走动。
  - ❓ 时间紧就退化为固定机位，指令照样能下；走动是 P1，不做也能录屏。

### 空间与锚点

房间约 6m × 8m，开放式布局（无隔断），6 个锚点：

| id | 中文 | 语义（写进提示词的就是这句） | 位置 |
|---|---|---|---|
| `door` | 门口 | 进屋的木门，门边挂着风铃 | 房间一端 |
| `window` | 窗边 | 望海的大窗，能看见灯塔的光扫过海面 | 北墙 |
| `lamp` | 灯桌 | 屋子中央的灯桌，主灯在这里（阿澄的默认位） | 正中 |
| `hearth` | 炉边 | 暖炉，有炭火红光 | 南墙 |
| `center` | 屋中央 | 灯桌旁的空地 | 中央偏东 |
| `player` | 你 | 玩家位置（伪锚点：只作 `look_at` 目标，不可寻路、不可 spawn） | 动态 |

锚点图（`move` 的可行路径，BFS 最短路）：

```
door ── center ── lamp
          │         │
        window ── hearth
```

边：`door–center`、`center–lamp`、`center–window`、`lamp–window`、`center–hearth`、`lamp–hearth`。
❓ 建场景时可按实际摆位微调边，锚点 id 不变。

**为什么用锚点图而不是 NavMesh**：50h 里 Unity 零基础，NavMesh 要烘焙 + 调参 + 排错；锚点图是"预设点 + 预设边 + 直线插值"，确定、可调试，而且和"LLM 只在语义锚点里选"的设定天然一致。

## 2. 三条指令的参数格式

统一结构：`{"op": "<指令>", ...参数}`，`op` 三选一。

| op | 参数 | 语义 | 合法条件 | 非法时 |
|---|---|---|---|---|
| `spawn` | `anchor`（必填）、`name`（选填，≤8 字） | 在锚点生成一只灯灵 | 锚点存在且不是 `player`；场上灯灵 ≤ 5 只 | 整批丢弃 |
| `move` | `entity`（必填：`npc` 或 `wisp_N`）、`anchor`（必填） | NPC 沿锚点图走过去；灯灵直线飘过去 | 实体存在；锚点存在；`player` 不可作目的地 | 整批丢弃 |
| `look_at` | `entity`（必填，目前只有 `npc`）、`target`（必填：锚点名或 `player`） | NPC 转身面向目标（0.5s 平滑转身） | 实体存在；target 存在 | 整批丢弃 |

约定：

- `entity` 在提示词里要求显式写；客户端缺省按 `npc` 处理。
- 灯灵 id 由客户端生成：`wisp_1`、`wisp_2`……
- **不做**（v2 再说）：自由坐标、自由寻路、生成可对话 NPC、改材质/天气/时间、多场景。

## 3. LLM 返回格式

### 响应（LLM → 客户端）

```json
{
  "say": "好，我去窗边，给你叫一只灯灵。",
  "commands": [
    { "op": "move",    "entity": "npc",  "anchor": "window" },
    { "op": "spawn",   "anchor": "window", "name": "小萤" },
    { "op": "look_at", "entity": "npc",  "target": "player" }
  ]
}
```

| 字段 | 类型 | 规则 |
|---|---|---|
| `say` | string | 角色口吻，≤2 句，可空串；先播这句，再执行指令 |
| `commands` | array | 0–5 条，按序执行；空数组 = 只说话 |

### 请求（Unity → 编排服务）

```json
{
  "player_text": "去窗边，叫一只灯灵出来，然后看向我",
  "world": {
    "anchors": [
      { "id": "door",   "desc": "进屋的木门，门边挂着风铃" },
      { "id": "window", "desc": "望海的大窗，能看见灯塔的光扫过海面" },
      { "id": "lamp",   "desc": "屋子中央的灯桌，主灯在这里" },
      { "id": "hearth", "desc": "暖炉，有炭火红光" },
      { "id": "center", "desc": "灯桌旁的空地" }
    ],
    "entities": [
      { "id": "npc",    "kind": "npc",  "at": "lamp" },
      { "id": "wisp_1", "kind": "wisp", "at": "window" }
    ]
  }
}
```

`world` 就是"世界快照"：LLM 只能从快照里选锚点和实体，选不存在的就判非法。这是不做自由寻路还能"看起来智能"的关键。

### 校验与失败策略（两层）

1. **服务端**：严格 JSON 解析 + 结构校验（字段、枚举、数量）。失败 → 带错误信息重问 **1 次**；仍失败 → 兜底 `{"say": "……我好像没听清，再说一遍？", "commands": []}`。
2. **客户端**：执行前**全量校验**（op 合法 / 实体存在 / 锚点存在 / ≤5 条）。任一非法 → **整批不执行**（不做半截），NPC 说"这个我做不到"，Console 打日志。
3. 执行顺序：先播 `say`（打字机），再逐条执行，条间 0.3s 缓冲；`say` 为空则直接执行。

### 兜底（对着录屏用）

服务端带 `--offline` 开关：读 `demo_lines.json`，按 `player_text` 精确匹配返回预置响应；匹配不到走固定话术。录屏时打开，不怕断网 / 限流 / 模型抖动。

## 4. 技术架构

```
Unity 客户端                        FastAPI 编排服务                  LLM（OpenAI 兼容）
┌───────────────────────┐   HTTP    ┌──────────────────────┐   HTTPS   ┌──────────────────┐
│ DialogueUI（输入/气泡） │ ────────> │ POST /direct         │ ────────> │ chat/completions │
│ DirectorClient        │ <──────── │ 提示词组装+校验+重试   │ <──────── │                  │
│ WorldState（锚点/实体） │           │ 日志                 │           └──────────────────┘
│ CommandExecutor       │           │ GET /health          │
│ AnchorGraph / NpcAgent│           │ --offline 回放        │
│ WispSpawner           │           └──────────────────────┘
└───────────────────────┘
```

- **Unity 6 LTS + URP 3D 模板**；Bloom 后期；TextMesh Pro；JSON 用 Newtonsoft（`com.unity.nuget.newtonsoft-json`）。
- **不让 Unity 直连大模型**：API Key 不能进客户端；校验 / 重试 / 日志在服务端才像工程；换模型只改一处。
- 服务端为本仓库自带的小服务（**不依赖已有桌宠后端**），约 150–200 行：`POST /direct`、`GET /health`、离线回放。
- 延迟预算：首字 < 2s；Unity 请求超时 8s，超时 → 兜底话术，不卡死。

### Unity 侧模块

| 模块 | 职责 | 估算 |
|---|---|---|
| `WorldState` | 锚点表（6）、实体表（npc + wisps）、当前位置 | 2h |
| `AnchorGraph` | 邻接表 + BFS 最短路 | 2h |
| `NpcAgent` | 沿路径插值走（1.2 m/s）+ 到点转身；`look_at` 平滑转向 | 4h |
| `WispSpawner / WispMotion` | 发光球 + 点光 + 上下浮动；飘向锚点 | 3h |
| `CommandExecutor` | 逐条执行 + 校验 + 日志 | 2h |
| `DialogueUI` | 输入框、气泡、打字机、"思考中"提示 | 3h |
| `DirectorClient` | UnityWebRequest + JSON + 超时 | 2h |
| `PlayerController`（P1） | 第一人称走动 | 3h |
